# VAIXLNS — واجهات النظام

هذه الوثيقة تفرز واجهات VAIXLNS على مستوى الاستخدام والتكامل، مع إبقاء المصطلحات الأساسية للمشروع كما هي.

## 1. سطح المكتب
المستودع المرشح الحالي: `desktop`

الواجهة الرئيسية للعمل المكثف، وتُبنى حول:
- التشغيل والمراقبة
- عرض العلاقات بين منظومات VAIXLNS
- التحكم في V-Kernel و VX و VV
- عرض XV/SCS و SUF و Intelligence Gateway
- Simulation Engine
- لوحات متعددة في مساحة عمل واحدة

## 2. الهاتف
المسار المقصود: واجهات الهاتف المرتبطة بالنظام.

المبدأ:
- نفس منطق النظام
- تكيف مع الشاشة الصغيرة
- اختصار العرض دون اختزال البيانات الأساسية
- انتقال سريع بين الحالات والعمليات

## 3. شاشات الأسهم
تُعامل كشاشات تشغيلية داخل منظومة VAIXLNS، وليست منتجاً منفصلاً.

المبدأ:
- بيانات لحظية
- سياق متعدد
- مؤشرات وحالات تشغيل
- ربط مباشر بطبقات النظام عند توفر التكامل

## 4. الواجهة العميقة
الواجهة لا تكون مجرد صفحات؛ بل طبقة عرض لحالة النظام.

تُظهر عند الحاجة:
- الحالة
- التدفق
- المصدر
- العلاقة
- القرار/التنفيذ
- المحاكاة
- السجل

## 5. واجهة العلاقات
عرض شبكي/ترابطي للعناصر الموجودة فعلياً في النظام، مع إمكانية الانتقال من العنصر إلى مصدره ومساره وتشغيله.

## 6. واجهة التشغيل
نقطة الانتقال من العرض إلى التنفيذ:
`Input → Intelligence Gateway → V-Kernel / VX / VV → Execution → Result → Trace`

## 7. واجهة المحاكاة
تجعل Simulation Engine مرئياً للمستخدم:
- الحالة الابتدائية
- السيناريو
- التدفقات
- النتائج
- الفروقات
- العودة إلى حالة سابقة

## 8. مبدأ موحد
كل واجهة يجب أن تحدد:
- ماذا تعرض؟
- من أين تأتي البيانات؟
- ما الذي يمكن تنفيذه؟
- ما أثر التنفيذ؟
- كيف يمكن تتبعه والعودة عنه؟

## فرز المستودعات المرتبطة بالواجهات — وفق الحالة الحالية
- `desktop`: واجهة سطح المكتب، وتحتاج التعامل مع `development` كفرعها الافتراضي الحالي.
- `react-native-website`: أصل/مرجع تقني محتمل للويب/React Native؛ لا يُعتبر واجهة VAIXLNS أساسية تلقائياً.
- `VAIXLNS`: المرجع canonical للتوثيق والفهرسة.
- `VAIXLNS-unified`: التكامل والتنفيذ الموحد، وليس واجهة مستقلة.
- `VX-runtime`: طبقة التشغيل، وليست واجهة عرض.
- بقية المستودعات لا تُصنّف كواجهة قبل فحص محتواها.

## قاعدة
لا يتم نقل أو حذف أو دمج أي مستودع لمجرد التشابه في الاسم. الفرز يعتمد على المحتوى الفعلي والعلاقة التشغيلية.
