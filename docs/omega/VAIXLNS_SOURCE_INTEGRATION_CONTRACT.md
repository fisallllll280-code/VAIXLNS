## Fable-derived engineering patterns

The integration records architectural patterns, not model identity claims:

- long-horizon task decomposition
- explicit planning before execution
- delegated parallel work with a controlling orchestrator
- persistent task state and recovery
- tool-mediated execution
- verification of generated work against an explicit brief
- bounded context/memory management
- failure-aware fallback handling

These patterns are mapped into VAIXLNS as implementation requirements rather than copied as an external system prompt.

## State separation

Epistemic state and authority state are independent.

Epistemic:
UNFORMED → PROPOSED → EVIDENCED → PROVEN → VALIDATED → SUSPECT → INVALIDATED

Authority:
UNAUTHORIZED → ELIGIBLE → AUTHORIZED → ACTIVE → SUSPENDED → REVOKED

No epistemic state automatically grants authority.
