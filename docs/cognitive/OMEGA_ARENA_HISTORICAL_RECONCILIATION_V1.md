## 3. Invention attribution model

The innovation rule is implemented conceptually as a lineage record, not a separate memory product.

- invention_id
- invention_fingerprint
- originator_type
- originator_id
- first_observation_event

- contributing_minds
- contributing_capabilities

- execution_evidence
- verification_evidence
- replay_evidence
- success_count
- revalidation_window
- champion_window
- status
- supersedes
- superseded_by

### Attribution rule

The originator is the earliest evidenced source of the novel proposal.

A later model/team that improves or executes the same invention receives contributor/derivation credit, not retroactive origin credit.

If novelty cannot be established against historical memory, the record remains unresolved rather than assigning false authorship.

## 4. Tournament result semantics

The historical No-Permanent-Winner rule is preserved.

Operational tournament rule:

TOURNAMENT_CHAMPION = best validated capability composition within a frozen evaluation window

Therefore:

- Champion is time-bounded.
- Champion is task/domain/constraint scoped.
- Champion requires evidence and replay.
- Champion does not establish universal model superiority.
- A later tournament may produce a different champion.
- Historical champions remain permanently recorded in lineage.

## 5. Seven-day cycle

The seven-day protocol is a DERIVED operational proposal:

FREEZE → BASELINE → CAPABILITY TRIALS → EXECUTION → ADVERSARIAL TEST → REPAIR/COMPOSITION → REPLAY/AUDIT → FINAL CHAMPION

Day-seven announcement is valid only after:

1. required deterministic tests complete;
2. evidence bundle is complete;
3. replay succeeds where required;
4. attribution records are sealed for the evaluation window;
5. hard safety/integrity gates pass;
6. the independent audit boundary is complete.

No announcement is authoritative merely because a model has the highest preliminary score.
