## 6. Remaining engineering gaps — ordered

1. **Corpus/lineage closure:** reconcile the 69-file local snapshot into the canonical source inventory with exact hashes, duplicate groups and inclusion/exclusion reasons; acquire the original item-by-item 0001–2750 index.
2. **One admitted runtime path:** resolve overlaps between the canonical 13-role registry, VX specialist runtime, and open reference orchestration kernels. Keep one canonical owner; use adapters/contracts rather than parallel authorities.
3. **Live provider proof:** explicitly configure permitted model endpoints and each required tool adapter; capture endpoint/model/version identity, timeouts, costs, failures, input/output digests and reproducible run evidence.
4. **Canonical durable operations:** bind event receipts and artifact archives to the VAIXLNS canonical ledger, enforce atomic idempotency, test tamper/restart/replay and define crash-resume semantics.
5. **Action-gate hardening:** trusted approval signature verifier, adapter-level timeout/cancellation, universal bypass tests and independent security verification.
6. **Admission/release:** require sandbox, failure injection, independent verification, replay, fresh proof, explicit authority, rollback and sustained observation before any production admission.
7. **Distributed/formal foundations:** implement and test leader election/replication/consensus and a real proof backend before claiming those capabilities.
8. **Canonical audit freshness:** refresh snapshots when source corpus/repository head changes; never let a generated catalog promote an item automatically.
