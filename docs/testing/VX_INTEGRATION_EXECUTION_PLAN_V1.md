# خطة تنفيذ اختبارات تكامل VX

وثيقة نهائية للتنفيذ والمراجعة  •  VX-INT-EXEC-001  •  الإصدار 1.0

الترتيب الملزم: `T01–T05` ثم `T06–T10` ثم `T15` ثم `T11–T14`.

الحالة: إعداد الوثيقة مكتمل؛ جميع الاختبارات NOT_RUN في هذه المهمة. صلاحية البدء مشروطة باجتياز G0؛ نجاح أي تشغيل سابق لا يثبت تلقائيًا اجتياز هذه الخطة. النطاق: مسار VX الفعلي والعقود المسجلة للأنظمة الأربعة؛ لا يُفترض اتصال أي نظام مسبقًا.

### عقد التشغيل والمسؤوليات

ينفّذ مهندس الاختبار على فرع مستقل، ويصلح المطور على الفرع نفسه، ويتحقق مراجع ذو هوية وصلاحيات منفصلة من الأدلة. تُسجّل أسماء المسؤولين في سجل التشغيل قبل البدء. سقف الإنفاق الخارجي صفر ريال؛ لا نشر ولا دمج إلى main ضمن هذه الخطة، ولا تفعيل حافة معطلة دون استيفاء عقدها وصلاحيتها.

يحظر تعديل أو حذف أو نقل project.genome ومرجع Ω.000 ونسخه القنونية. المرجع المرصود في VAIXLNS: registry/omega/omega-000-master-index.json. تُحصر بقية الأسماء والروابط المرجعية قبل التشغيل؛ تعذر حصرها يوقف G0. لا يُعالج فشل اختبار بتغيير هذه الملفات.

### G0 — التحضير الإلزامي قبل T01

يُجرد VAIXLNS وVX-runtime والمستودعات المرتبطة بالعقود، مع تمييز المتاح من المحجوب وعدم استنتاج هوية NEXENT/NEXNET من تشابه الاسم. تُثبت لكل مستودع: remote، الفرع، commit SHA كامل، ملفات القفل، إصدارات التشغيل، العقود والسياسة، وصلاحيات التنفيذ. تُستخدم بيانات اصطناعية وبيئة اختبار معزولة ونسخة استعادة قبل حقن أي فشل.

ينشأ worktree مستقل لكل مستودع، من نسخة origin/main المقروءة بعد الجلب. الأوامر أدناه تُنفّذ داخل المستودع المعني؛ ثم يُستكمل العمل داخل worktree الجديد:

```bash
VX_RUN="$(date -u +%Y%m%dT%H%M%SZ)"
VX_REPO="$(basename "$(git rev-parse --show-toplevel)")"
git fetch origin main
git worktree add -b "test/vx-int-$VX_RUN" "../$VX_REPO-vx-int-$VX_RUN" origin/main
```

تُحفظ قائمة الملفات المحمية وبصمات SHA-256 لبايتاتها في سجل خارجي للقراءة فقط؛ تُقارن قبل كل مجموعة وبعدها، مع فحص git diff للملتزم والمجهز وغير المجهز، ورصد الحذف والإضافة وإعادة التسمية. أي فرق يوقف التشغيل. تُحفظ بصمات Git blob منفصلة عن SHA-256 ولا تُقارن إحداهما بالأخرى.

يُنشأ test-map لكل T01–T15: المستودع، نقطة الاختبار الدقيقة، الأمر، المتطلبات، المالك، المتوقع ودليل التغطية. تُراجع التوكيدات في الشيفرة؛ الاسم وحده لا يكفي. الاختبار المفقود يُنفّذ على الفرع قبل بدء مجموعته، وإلا يُسجل BLOCKED؛ لا تبقى خانات مجهولة عند فتح البوابة.

### تسجيل الأدلة وتنفيذ الأوامر

تُنشأ حزمة evidence/<run_id>/<test_id>/<attempt>/ خارج الملفات المحمية، وتحوي: الأمر وبيئة التشغيل، stdout/stderr منقحين، exit_code، تقرير توكيدات آلي، المدخلات وبصماتها، الحالة قبل/بعد، وقرار المراجع. يحفظ manifest بصمة SHA-256 لكل قطعة؛ يُحفظ manifest.sha256 منفصلًا دون أن يدرج نفسه. لا تُحذف المحاولات الفاشلة.

```text
test_id, run_id, attempt, repository, source_commit, command, env_hash,
policy_hash, input_hash, started_at_utc, ended_at_utc, exit_code,
expected, actual, artifact_refs, artifact_sha256, verdict, verifier
```

يعاد حساب البصمات من القطع نفسها. تُربط تقارير CI برابط التشغيل وjob وcommit؛ وفي التشغيل المحلي يُحفظ أمر إعادة الإنتاج. حفظ البصمات وحده لا يثبت استقلال المراجع؛ يلزم سجل بهويته في صلاحيات منفصلة.

### معالجة الفشل وإعادة القبول

عند أول FAIL أو BLOCKED أو نتيجة مجهولة: أوقف الانتقال، جمّد الأدلة وافتح سجل عيب يتضمن test_id والالتزام والسبب والأثر وأمر إعادة الإنتاج. اعزل الطرف المتأثر واستعد آخر لقطة سليمة عند الحاجة. اختلاف ملف محمي أو تسرب سر أو تجاوز سلطة حادث مانع؛ تُحفظ الأدلة المنقحة ويعزل الوصول فورًا.

لا تُعاد المحاولة بلا تفسير. بعد إصلاح على الفرع الآمن تُنشأ محاولة وcommit جديدان، وتُعاد الاختبارات المتأثرة وتبعياتها وجميع البوابات اللاحقة؛ تغيير السياسة أو المصدر لا يسمح باستخدام أدلة النسخة القديمة دون إعادة تحقق. تظل نتيجة المحاولة السابقة محفوظة؛ الاختبار المتذبذب لا يُقبل باختيار محاولة ناجحة.

### G5 — محضر الإغلاق الذي يوقعه المراجع
