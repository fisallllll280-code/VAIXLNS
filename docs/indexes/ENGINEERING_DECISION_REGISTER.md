# VAIXLNS — Engineering Decision Register

This is a concise design rationale record, not private chain-of-thought.

| Decision | Rule | Basis |
|---|---|---|
| Canonical root | Keep `VAIXLNS` as architecture/registry/doc root | The repository already contains V6, recovery audit, registry schema, innovation catalog and templates. |
| Execution root | Keep `VAIXLNS-unified` as runtime surface | It contains identity/ledger/constitution, deterministic execution, state machine, VX runtime and replay tests. |
| Discovery root | Keep `NEXENT` as research/discovery surface | It contains master inventory, architecture search, innovation and adoption materials. |
| Core slice | Keep `vaixlns-core` focused | Prevents the small executable core from becoming coupled to the whole documentation graph. |
| CSD | Keep `vaixlns-csd-kernel` specialized | It is a specialized signed/replay kernel surface. |
| Intent | Keep `VAIXLNS-Intent-to-Reality` focused | It owns intent→reality pipeline material. |
| Build | Keep `VX50_COMPLETE_BUILD` as build surface | Separates developer/build concerns from canonical governance. |
| History | Never silently erase historical names | Provenance/lineage are part of the recovery objective. |
| Truth | Observation ≠ Evidence ≠ Proof ≠ Authority | Prevents readiness signals becoming legitimacy claims. |
| Boundary | NEXENT proposes; VAIXLNS governs/adopts | Keeps research separate from execution authority. |
| Coverage | Do not claim all 2750 rows are recovered | The corpus confirms the span, not every item-by-item record. |
