## 5. Engineering readiness vocabulary

Use per-item, evidence-backed states rather than one vague “ready” flag:

- \`RECOVERED\`: extracted from a source with a source locator/digest and original/derived classification.
- \`CANONICAL\`: authorized owner and placement are established.
- \`PROPOSED\`: design hypothesis; no implementation implied.
- \`SPECIFIED\`: interface/contracts/acceptance conditions exist; no runtime implied.
- \`IMPLEMENTED\`: code artifact exists at an identified revision.
- \`TESTED\`: identified test suite passed for that revision; not equivalent to validation.
- \`VERIFIED\`: the exact stated claim is supported by reproducible proof/evidence.
- \`VALIDATED\`: behavior is checked against an independent domain reference or experiment where required.
- \`LIVE_VERIFIED\`: live integration/endpoint is authenticated and a revision-bound health/behavior test succeeded.
- \`BLOCKED\`, \`CONFLICT\`, \`UNKNOWN\`, \`INCONCLUSIVE\`: retain openly; never transform these into PASS by omission.

A missing metric, skipped test, unqueried repository, absent source digest or unresolved naming conflict must not count as a successful result.

## 6. Shortest safe execution sequence

### Wave 0 — Preserve and establish the baseline
1. Record revision, source-file inventory and SHA-256 for each ingested source.
2. Run the deterministic operation-index generator and validator in check mode.
3. Produce a coverage receipt: searched repositories/branches, inaccessible sources, query lanes, extracted atomic records, duplicates, conflicts and historical ID gaps.
4. Keep \`NEXENT/NEXNET/NEIENT\` and \`VLNS/NAXLNS\` identity collisions unresolved until an authoritative repository mapping is proved.

### Wave 1 — Make the invention engine evidence-driven
1. Register existing capabilities from VX Invention Engine and the 97-name portfolio without inventing duplicate top-level systems.
2. Each capability receives identity, owner, inputs/outputs, assumptions, invariants, contracts, dependencies, authority envelope, failure cases, evidence refs, test refs and lineage.
3. Connect the Architecture Laboratory to candidate generation through typed contracts; keep candidates isolated.
4. Add explicit falsification, duplicate/lineage review and independent verification to every candidate.

### Wave 2 — Close mathematical/computational execution
1. Route candidate models to VCRE/V-MATH/V-PHYSICS and VX through explicit model and runtime contracts.
2. Require dimensional checks, validity domain, initial/boundary conditions, invariants, numerical tolerance, error estimate and uncertainty model.
3. Emit model + solver/version + input fingerprint + environment + test/evidence + uncertainty + replay manifest.
4. Keep simulated, inferred, measured, formally proven, numerically verified and experimentally validated states separate.

### Wave 3 — Accelerate without weakening assurance
1. Preflight static/schema/security checks, then focused unit tests, then cross-contract tests, then golden replay/recovery, then scheduled deep tests.
2. Parallelize independent jobs while keeping authorization, provenance, identity, evidence and canonical-admission gates mandatory.
3. Use impact-aware selection only when mapping is complete; fall back to full suite for unknown/ambiguous impact.
4. Measure repeated baseline/p50/p95, queue time, test duration, cache hit rate, failure rate and flakiness before claiming a speedup.

### Wave 4 — Turn failures into reusable engineering knowledge
1. Capture failure signature, source revision, conditions, minimal reproducer and evidence digest.
2. Propose a regression test/invariant/Ω-Pattern; do not automatically call a failure a universal law.
3. Test the derived rule against counterexamples and other affected systems.
4. Promote only after independent verification and authorized review; preserve rejected/obsolete variants with lineage.
