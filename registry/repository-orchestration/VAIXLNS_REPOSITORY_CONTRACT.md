## Authority

Canonical architecture and lineage are governed by VAIXLNS. Discovery and research proposals originate through the federated discovery layer.

## Required evidence

A repository is not VERIFIED from documentation alone. Verification requires a reproducible entrypoint, dependency resolution, execution, tests, and captured evidence.

## Lifecycle

~~~text
PROPOSAL → SEEDED → IMPLEMENTED → TESTED → VERIFIED → EVOLVING
                         ↘ FAILED / QUARANTINED
~~~

## Contract

Declare: entrypoint, build command, test command, runtime dependencies, external interfaces, security boundary, canonical lineage, evidence path, performance metrics and innovation records.

## Anti-duplication

Before introducing a new top-level system, reconcile against the VAIXLNS repository federation and innovation indexes. Overlap should become a derived capability record unless a new system boundary is justified by contract and evidence.
